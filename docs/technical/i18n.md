# Internationalization

Keep Tabs is translated into **English** (the default locale) and **French**.
It follows the browser's language: a browser in French shows Keep Tabs in
French, a browser in any language Keep Tabs is not translated into shows it in
English.

## Where the texts are

Every text shown to the user is in `src/_locales/<lang>/messages.json`, the
format of `chrome.i18n`. None is written in the code.

| Where the text appears | How it is filled |
|---|---|
| `manifest.json` (name, description, tooltip of the icon) | `__MSG_key__`, replaced by the browser. |
| Pages of Keep Tabs (popup, restore report, welcome page) | A `data-i18n="key"` attribute; the page's script puts the message in the element when it loads. |
| Texts built by a script | `message('key')`, or `pluralMessage('key', count)` for a text with a number. |
| Session file | Translated when the file is saved, then written into it (see [below](#language-of-the-session-file)). |

## Rules for keys

- Names are `camelCase` and say where the text is used: `saveButton`,
  `restoreFailed`, `welcomeStepSave`.
- Every key exists in **every** locale, with the same placeholders.
- Every key has a `description` for translators, in English, saying where the
  text is shown and what it means. Translators keep descriptions in English.
- A placeholder that receives an error message (`$ERROR$`) shows a text from
  the browser, which is in English.

### Plurals

`chrome.i18n` has no plural support. A text with a number is a pair of keys
suffixed `_one` and `_other` (`windowTabCount_one`, `windowTabCount_other`).
`src/lib/plural.js` picks the form with `Intl.PluralRules`, in the language of
the messages: French uses the `_one` form for 0 and 1, English only for 1.
Languages with more forms ("few", "many") fall back to `_other`.

### The `languageCode` key

`languageCode` is not a sentence: its message is the code of the language of
the file (`en`, `fr`). The browser's language and the language of the messages
can differ: a browser in German shows Keep Tabs in English. The scripts use
`languageCode` wherever the language of the messages matters, so that the
text, its plural form and its date format agree:

- choosing the plural form;
- formatting the date of a session;
- the `lang` attribute of the session file.

### French typography

- A non-breaking space before `:`, `;`, `!` and `?`, and inside `«` and `»`.
  It is written `\u00a0` in `messages.json`, so it stays visible when the file
  is edited.
- Straight apostrophes (`'`), as in the rest of the file.
- The names of browser settings are written exactly as the browser shows them
  in French: « Autoriser l'accès aux URL de fichier ».

## Language of the session file

A session file is written in the language active **when it was saved**: its
summary, its date, the "pinned" badges and the messages it shows on its own
do not change if it is opened later in a browser in another language (see
[Session file format](session-file-format.md#structure-of-the-html)). The
session name is the one the user chose, never translated.

The restore report, shown inside the session file, is a page of Keep Tabs: it
follows the language of the browser that restores the file.

## Automatic checks

`tests/locales.test.js` runs with `npm test` and checks that:

- English and French exist, and English is the default locale;
- key names follow the rules above, and every plural key has both forms;
- every locale has the same keys and placeholders, and every key has a message
  and a description;
- the name and description fit the Chrome Web Store limits (75 and 132
  characters);
- the code only asks for keys that exist, in `data-i18n="…"`, `message('…')`,
  `pluralMessage('…')`, ``message(`…_${…}`)`` and `__MSG_…__`;
- every key is used somewhere in the code, so translators never translate a
  text that is not shown.

A key written elsewhere, such as the two keys of `saving ? 'savingButton' :
'saveButton'` or the reasons listed in `receiver.js`, is not checked when it is
asked for. A typo there is still caught in most cases: the right key is then
used nowhere, and the second check fails.

The second check only looks for the key between quotes anywhere in the code.
A key that is only mentioned in a comment, or that has the same name as
another string, counts as used.

## Testing in another language

Chrome shows extensions in the language of its interface:

- **Windows:** `chrome://settings/languages`, then **Display Google Chrome in
  this language** next to the language, and restart Chrome.
- **macOS:** the order of languages in the system settings, or Chrome's own
  language in **System Settings → General → Language & Region → Applications**.
- **Linux:** start Chrome with the `LANGUAGE` environment variable, for example
  `LANGUAGE=fr google-chrome`. Quit Chrome completely first: otherwise the
  command only opens a window in the running Chrome, which keeps its language.

Then check every page: the popup (with and without warnings), a session file
opened with and without Keep Tabs, the restore report and the welcome page.

## Adding a language

Languages other than English and French are out of scope for v1 (see the
[roadmap](../roadmap/v1.md)). Later, adding one means:

1. Copy `src/_locales/en/` to `src/_locales/<code>/`, with the code of the
   language as Chrome expects it (`de`, `pt_BR`…).
2. Translate every `message`, keep every `description` in English, and set
   `languageCode` to the language's code. This one is a language tag, with a
   hyphen (`de`, `pt-BR`), not the folder name: `Intl` rejects `pt_BR`, and
   the plurals and dates would stop working.
3. Add the language to the list expected by `tests/locales.test.js`, to this
   page and to `AGENTS.md`.
4. Test it in a browser in that language, as described above.
