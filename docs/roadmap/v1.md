# Keep Tabs v1 — scope

This page defines what version 1 of Keep Tabs does, and what it does not do.
Anything not listed under [In scope](#in-scope) is out of scope for v1.

## Goal

Let a user turn a browser window into a file, close the window, and later get
it back **exactly as it was** with a double-click on that file — as if the
window had never been closed.

## User flows

### Save a window

1. The user clicks the Keep Tabs icon in the window they want to save.
2. A form opens with:
   - a **file name** field, empty, whose placeholder shows the default name
     (see [File name](#file-name));
   - a **lazy loading** toggle, on by default;
   - a **Save** button.
3. Clicking **Save** opens the system "Save as" dialog, starting in the
   user's **Desktop** folder. The user can pick any other folder.
4. Once the file is written, the form confirms it and offers a
   **Close window** button.

### Restore a window

1. The user double-clicks the session file. It opens in their default
   browser.
2. Keep Tabs recognizes the page as one of its session files.
3. It creates a new window identical to the saved one.
4. It closes the session file's tab. If that tab was alone in its window, the
   window is closed too, so only the restored window remains.

The session file is **not** modified or deleted: it can be restored again as
many times as needed.

### Open a session file without Keep Tabs

If the extension is not installed (or cannot read local files), the session
file is still a readable page showing:

- the session name and date;
- the list of saved tabs as links, grouped by tab group;
- a short explanation of how to restore it automatically with Keep Tabs,
  including the "Allow access to file URLs" setting.

### First run

Right after installation, Keep Tabs opens a welcome page that explains how it
works and checks whether **Allow access to file URLs** is turned on. If it is
not, the page explains how to turn it on. Without it, session files cannot be
restored.

## In scope

### What is saved

For the window:

- position and size;
- state: normal, maximized or fullscreen.

For each tab, in order:

- URL and title;
- pinned state;
- whether it is the active tab;
- the tab group it belongs to, if any.

For each tab group:

- name, color, and collapsed state.

Supported pages include regular web pages, online and local PDF files,
local files (`file://`), browser pages (`chrome://…`) and pages of other
installed extensions.

### Restoration fidelity

- Tabs reopen in the same order, with the same pinned state, groups, active
  tab, window position, size and state.
- If the saved position is outside the current screens (for example, a
  disconnected monitor), the window is placed on the current screen.
- With **lazy loading** on, only the active tab loads immediately; the others
  load when the user selects them. The choice made when saving is stored in
  the file.
- Being logged out of some websites after a restore is accepted: the browser
  profile keeps cookies, but sessions may have expired.

### Pages that cannot be restored

Some tabs have temporary content that disappears when they are closed
(`blob:` URLs, generated previews). When saving, Keep Tabs lists these tabs
and warns that they will not be restorable.

### File name

The placeholder, used when the field is left empty, follows this pattern:

```
KeepTabs_<count>-<tabs>_<YYYY-MM-DD>_<HH-mm-ss>.html
```

- `<tabs>` is translated and agrees with the count: `1-tab`, `8-tabs` in
  English; `1-onglet`, `8-onglets` in French.
- Date and time are local, with `-` instead of `:` (forbidden on Windows).
- Characters forbidden in file names (`/ \ : * ? " < > |`) typed by the user
  are replaced automatically.

Example: `KeepTabs_8-tabs_2026-11-02_14-35-08.html`.

### Session file

- A single, self-contained HTML file: no external resources, so opening it
  makes no network request.
- It embeds the saved data as JSON, with a format version number so future
  versions of Keep Tabs can still read v1 files.
- Its visible text is written in the language active when it was saved.
- The exact format is documented in `docs/technical/session-file-format.md`.

### Security

- Tab titles and URLs are escaped when written into the file.
- On restore, the file content is validated, and only URLs with an allowed
  scheme are opened. `javascript:` URLs are always rejected.

### Languages

English (default) and French, following the browser's language.

### Browsers

Chromium-based browsers: Google Chrome is the reference, Microsoft Edge and
Brave are tested before release. Windows, macOS and Linux.

## Out of scope for v1

| Feature | Note |
|---|---|
| Updating an existing session file | Planned for a later version. |
| List of saved sessions inside the extension | Files are the only storage. |
| Tab history (back / forward), scroll position, form content | Not accessible to extensions. |
| Saving several windows at once | One window per file. |
| Incognito windows | Keep Tabs shows a message saying they cannot be saved. Possible later. |
| Keyboard shortcut | Possible later. |
| Settings page (default folder, default toggle value…) | Possible later. |
| Favicons in the session file | Would require network requests or bigger files. |
| Firefox and Safari | Different extension platforms. |
| Languages other than English and French | Added later, through `_locales`. |

## Open questions

These points must be validated by a prototype before the implementation
starts.

1. **Detecting the session file.** Content script on `file://` pages (needs
   "Allow access to file URLs"), or redirection from the file to a page inside
   the extension (might avoid that setting).
2. **"Save as" dialog from the popup.** The popup closes when it loses focus,
   which may cancel the dialog. A small dedicated extension window may be
   needed.
3. **Desktop as the starting folder** on Windows, macOS and Linux.
4. **Lazy loading technique**: creating tabs without loading them, reliably,
   while keeping their title.

## Milestones

1. **Prototype** — answer the open questions above.
2. **Save** — form, capture of the window, session file generation.
3. **Restore** — detection, full-fidelity window recreation, lazy loading.
4. **Fallback page and welcome page.**
5. **Internationalization** — complete English and French.
6. **Store release** — privacy policy, permission justifications, listing
   texts, screenshots, `v1.0.0` tag.

## Definition of done

v1 is done when:

- every item in [In scope](#in-scope) works in Chrome, Edge and Brave;
- the pure logic in `src/lib/` is covered by unit tests;
- `docs/features/` and `docs/technical/` describe the actual behavior;
- the extension is published on the Chrome Web Store.
