# Keep Tabs v1 — scope

This page defines what version 1 of Keep Tabs does, and what it does not do.
Anything not listed under [In scope](#in-scope) is out of scope for v1.

## Goal

Let a user turn a browser window into a file, close the window, and later get
it back **exactly as it was** with a double-click on that file — as if the
window had never been closed.

## User flows

### Save a window

1. The user clicks the Keep Tabs icon in the window they want to save.
2. A form opens with:
   - a **file name** field, empty, whose placeholder shows the default name
     (see [File name](#file-name));
   - a **lazy loading** toggle, on by default;
   - a **Save** button;
   - a warning when needed (see [Local files](#local-files)).
3. Clicking **Save** opens the system "Save as" dialog, starting in the
   user's **Desktop** folder. The user can pick any other folder.
4. Once the file is written, the form confirms it and offers a
   **Close window** button.

### Restore a window

1. The user double-clicks the session file. It opens in their default
   browser.
2. The page reaches Keep Tabs and hands it the saved data (see
   [Technical decisions](#technical-decisions)).
3. Keep Tabs creates a new window identical to the saved one.
4. It closes the session file's tab. If that tab was alone in its window, the
   window is closed too, so only the restored window remains.
5. If some tabs could not be reopened, the session file's tab stays open
   instead and lists them, with the reason.

The session file is **not** modified or deleted: it can be restored again as
many times as needed.

### Open a session file without Keep Tabs

If the extension is not installed, the session file is still a readable page
showing:

- the session name and date;
- the list of saved tabs as links, grouped by tab group;
- a short explanation of how to restore it automatically by installing
  Keep Tabs.

### First run

Right after installation, Keep Tabs opens a welcome page that explains how it
works. It also presents the optional **Allow access to file URLs** setting,
only needed to reopen tabs that show local files, and tells whether it is on.

## In scope

### What is saved

For the window:

- position and size;
- state: normal, maximized or fullscreen.

For each tab, in order:

- URL and title;
- pinned state;
- whether it is the active tab;
- the tab group it belongs to, if any.

For each tab group:

- name, color, and collapsed state.

Supported pages include regular web pages, online and local PDF files,
local files (`file://`, see [Local files](#local-files)), browser pages
(`chrome://…`) and pages of other installed extensions.

### Restoration fidelity

- Tabs reopen in the same order, with the same pinned state, groups, active
  tab, window position, size and state.
- If the saved position is outside the current screens (for example, a
  disconnected monitor), the window is placed on the current screen.
- With **lazy loading** on, only the active tab loads immediately; the others
  load when the user selects them. The choice made when saving is stored in
  the file.
- Being logged out of some websites after a restore is accepted: the browser
  profile keeps cookies, but sessions may have expired.

### Local files

Browsers only let an extension open a local file (`file://`) when the user has
turned on **Allow access to file URLs** in the extension's details. Tabs
showing local files are always saved, so nothing is lost if the setting is
turned on later. When the setting is off:

- **when saving** a window that contains such tabs, the form warns that they
  will not reopen automatically, with a button that opens the setting;
- **when restoring**, the session file's tab stays open, lists the tabs that
  could not be reopened and shows the same button.

### Pages that cannot be restored

Some tabs have temporary content that disappears when they are closed
(`blob:` URLs, generated previews). When saving, Keep Tabs lists these tabs
and warns that they will not be restorable.

### File name

The placeholder, used when the field is left empty, follows this pattern:

```
KeepTabs_<count>-<tabs>_<YYYY-MM-DD>_<HH-mm-ss>.html
```

- `<tabs>` is translated and agrees with the count: `1-tab`, `8-tabs` in
  English; `1-onglet`, `8-onglets` in French.
- Date and time are local, with `-` instead of `:` (forbidden on Windows).
- Characters forbidden in file names (`/ \ : * ? " < > |`) typed by the user
  are replaced automatically.

Example: `KeepTabs_8-tabs_2026-11-02_14-35-08.html`.

### Session file

- A single, self-contained HTML file: no external resources, so opening it
  makes no network request.
- It embeds the saved data as JSON, with a format version number so future
  versions of Keep Tabs can still read v1 files.
- Its visible text is written in the language active when it was saved.
- The exact format is documented in `docs/technical/session-file-format.md`.

### Security

- Tab titles and URLs are escaped when written into the file.
- On restore, the file content is validated, and only URLs with an allowed
  scheme are opened. `javascript:` URLs are always rejected.
- The saved data never appears in an address, so it never reaches the browser
  history.
- The only part of Keep Tabs reachable from outside is the page that receives
  session data, and only from local files: websites can neither detect
  Keep Tabs nor send it data.

### Languages

English (default) and French, following the browser's language.

### Browsers

Chromium-based browsers: Google Chrome is the reference, Microsoft Edge and
Brave are tested before release. Windows, macOS and Linux.

## Out of scope for v1

| Feature | Note |
|---|---|
| Updating an existing session file | Planned for a later version. |
| List of saved sessions inside the extension | Files are the only storage. |
| Tab history (back / forward), scroll position, form content | Not accessible to extensions. |
| Saving several windows at once | One window per file. |
| Incognito windows | Keep Tabs shows a message saying they cannot be saved. Possible later. |
| Keyboard shortcut | Possible later. |
| Settings page (default folder, default toggle value…) | Possible later. |
| Favicons in the session file | Would require network requests or bigger files. |
| Firefox and Safari | Different extension platforms. |
| Other extension stores (Microsoft Edge Add-ons…) | Chrome Web Store only: see [Technical decisions](#technical-decisions). |
| Languages other than English and French | Added later, through `_locales`. |

## Technical decisions

A throwaway prototype answered the questions left open by this roadmap. It was
tested in Chrome 156 on Windows in November 2026.

### 1. Detecting the session file

**Decision:** the session file embeds a hidden frame that loads a page of
Keep Tabs, and sends the saved data to it as a message.

- It works **without** the "Allow access to file URLs" setting, which is off by
  default for extensions installed from the store.
- The data never appears in an address, so it is never stored in the browser
  history.
- The frame page is the only part of Keep Tabs reachable from outside, and
  only from `file://` pages: websites can neither detect Keep Tabs nor send it
  data.

Rejected alternatives:

| Alternative | Why it was rejected |
|---|---|
| Content script on `file://` pages | Does nothing until the user turns on "Allow access to file URLs". |
| Redirecting the file to a Keep Tabs page, data in the address | The whole session ends up in the browser history, which may be synced to the user's account. |

The frame's address contains the Keep Tabs extension ID, which is public. v1
is only published on the Chrome Web Store, so this ID is the same in every
browser that installs Keep Tabs from it (Chrome, Edge, Brave, Vivaldi, Opera).
A `key` in `manifest.json` gives the development build the same ID.

### 2. Saving the file

**Decision:** the file is written from the extension popup with the File
System Access API (`showSaveFilePicker`), starting in the Desktop folder.

The popup stays open while the "Save as" dialog is shown, so no dedicated
window is needed. The downloads API was rejected: its dialog starts in the
Downloads folder.

The Desktop starting folder is confirmed on Windows. macOS and Linux are
checked before release.

### 3. Lazy loading

**Decision:** non-active tabs are put to sleep (discarded) **last**, after all
tabs are created, grouped and the active tab is selected, and only once each
tab knows its URL and title.

- A tab discarded before its URL is known becomes an empty `about:blank` tab:
  the URL is lost. A tab whose URL is still unknown after a short delay is
  therefore left loaded rather than discarded.
- Discarding gives a tab a new ID, so no step may rely on a tab ID after it is
  discarded.

## Known limitations

- Chrome keeps closed tab groups itself ("saved tab groups", shown in the
  bookmarks bar). Each restore creates new groups, so these saved groups appear
  more than once. Extensions have no API to manage them.
- Tabs showing a local file (`file://`) can only be reopened when "Allow access
  to file URLs" is turned on (see [Local files](#local-files)).

## Milestones

1. **Prototype** — done, see [Technical decisions](#technical-decisions).
2. **Save** — form, capture of the window, session file generation.
3. **Restore** — detection, full-fidelity window recreation, lazy loading.
4. **Fallback page and welcome page.**
5. **Internationalization** — complete English and French.
6. **Store release** — privacy policy, permission justifications, listing
   texts, screenshots, `v1.0.0` tag.

## Definition of done

v1 is done when:

- every item in [In scope](#in-scope) works in Chrome, Edge and Brave;
- the pure logic in `src/lib/` is covered by unit tests;
- `docs/features/` and `docs/technical/` describe the actual behavior;
- the extension is published on the Chrome Web Store.
